# Implementation Principles

1. Inspect existing code and follow local conventions.
2. Prefer semantic HTML and accessible primitives.
3. Keep styling consistent with the selected tokens.
4. Use responsive CSS and content-aware constraints.
5. Avoid unnecessary dependencies.
6. Keep components focused and maintainable.
7. Use realistic content and meaningful data.
8. Implement loading, empty, error, and success states where relevant.
9. Ensure controls work; do not ship decorative fake controls.
10. Run available lint, typecheck, build, and tests.
11. Review changed files and avoid unrelated modifications.
12. Report any unverified behavior.

If the user asks for a visual-only concept, do not force implementation. If the user asks for code-first, keep the blueprint concise but still reason through design choices.
