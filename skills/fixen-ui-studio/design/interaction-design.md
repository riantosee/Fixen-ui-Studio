# Interaction Design

Specify behavior, not just appearance.

For each important control define:
- Purpose and expected result
- Default, hover, focus-visible, active, disabled, loading, success, and error states as relevant
- Keyboard interaction
- Touch target and mobile behavior
- Feedback and timing
- Reduced-motion behavior

Use motion to communicate state, continuity, hierarchy, or feedback. Avoid animation that delays tasks or distracts. Prefer native semantics and predictable controls. Do not create clickable-looking elements without real behavior.
